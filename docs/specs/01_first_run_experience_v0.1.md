# First-Run Experience v0.1

## 1) Front Matter

* **Title:** First-Run Experience v0.1
* **Version:** v0.1
* **Date:** 2025-12-16
* **Status:** Draft

## 2) Purpose

In the first 60 seconds, first-run onboarding proves that **Field-Kit is a persistent Field (not a chat app)** by (1) creating durable **Episode + Items + Bonds** and append-only **QDPIEvents**, and (2) **when the user opts into the Guided Tutorial Track**, demonstrating the **Queue Lattice Mode** end-to-end: minting **Queue Items**, creating **hololoop Bonds** to connect them, and then unlocking **operator execution** (at least **one Bond execution** that generates a **new output Item with lineage**, and at least **one Holologue run** that takes a **constellation (many Items/Bonds)** and produces **one specific new artifact Item**).

### Terms (v0.1)

* **Episode:** A local, user-owned container for one working session. Every persisted object and every QDPIEvent belongs to exactly one Episode via `episode_id`.
* **Item:** A persistent node of content in the Field, created by a user or generated by an operator. Items are addressable by ID and include a `type` (e.g., `Q`, `M`, `D`, `H`) plus content and minimal metadata.
* **Queue:** An Item with `type:"Q"`. Queue Items are artifacts, not prompts. They are the foundation of the Queue Lattice.
* **Bond:** A persistent instruction that connects one or more input Items to an operator run. `prompt_text` is the primary instruction. Bonds are created as `status:"draft"` and may be executed; execution generates exactly one output Item and MUST set `status:"executed"` and `output_item_id`. Bonds may also be **link-only** (hololoops between Queue Items) that are never executed.
* **Hololink:** A one-way navigational sentence connecting two Items. Hololinks are content-derived and reference handles from both Items.
* **Hololoop:** A two-way navigational loop formed by selecting hololinks in both directions between two Items. A hololoop becomes a persisted link-only Bond.
* **QDPIEvent:** An append-only event record that logs meaningful actions and results. Each event includes `qdpi` (Queue/Monologue/Dialogue/Holologue), `direction` (user→field or system→field), a `name`, a timestamp, and refs to related object IDs.
* **Proposal:** A system suggestion (e.g., suggested Bond prompts or hololoop options) that is logged as events only until the user explicitly confirms creation.
* **Canon:** A user-curated projection over Items/Bonds within an Episode used for presentation or replay. Canon never overrides the append-only event log.
* **Bundle:** A structured artifact output of a Holologue run (many→one) capturing what was selected, what was generated, and any optional proposals. A Bundle may be represented as a single output Item plus an exportable JSON payload.

## 3) Scope and Non-goals

### Scope (in v0.1)

* v0.1 is **Private • Local**: all Field data is stored locally on-device; no accounts and no cloud sync.
* First app open on a fresh install (no existing local Field data).
* One underlying environment: **Blank Field** (holographic default).
* Two onboarding tracks:

  * **A) Blank Field (default)**: minimal guidance, Queue Lattice Mode enabled.
  * **B) Guided Tutorial Track (optional)**: guided mini-workshop (3 moves), still on the same Blank Field with Queue Lattice Mode.
* Explicit creation and visible persistence of:

  * **Episode** (auto-created Session 0)
  * **Queue Item** (user-created; `type:"Q"`)
  * **Bond** (user-confirmed; draftable and executable, or link-only hololoop)
  * **QDPIEvent** (append-only log, always)
* Demonstrate Queue Lattice Mode in both tracks:

  1. **Queue Item creation** (minting artifacts, not prompts)
  2. **Hololoop selection** (4 options presented, user selects 1 → persists link-only Bond)
  3. **Lattice bootstrapping** (minimum 4 Queue Items before operators unlock)
* After lattice bootstrap, demonstrate the three representative operator moves in the Guided Tutorial Track:

  1. **Q→M** via suggested Bond execution (pick 1 of 4 suggestions → tap **Create Bond** → Run Bond → output Item generated)
  2. **Q→D** via user-written Bond prompt (write prompt → Run Bond → output Item generated)
  3. **(Q,Q)→H** via Holologue (select 2+ Items → Run Holologue → output artifact Item generated)
* A **Ledger** UI that makes object persistence and event append-only logging obvious.

### Credits (v0.1 simulation)

* Credits are **local-only** and **purely simulated** in v0.1.
* Credits are **not transferable**, **not redeemable**, and have **no USD exchange rate** in v0.1.
* Credits are represented as **append-only QDPIEvents** and the balance is a **derived view** (no new required core object in v0.1).

**Eventing (single pattern):**

* Event name: `credits.delta`
* Each credits change logs a QDPIEvent with `refs`:

  * `delta` (integer; positive or negative)
  * `balance_after` (integer)
  * `reason` (short string; e.g., `seed`, `item_created`, `bond_executed`, `holologue_completed`)
  * optional related refs (e.g., `item_id`, `bond_id`, `output_item_id`, `event_id`) when helpful

### Non-goals (explicitly out of scope for v0.1)

* Account creation, sign-in, cloud sync, or multi-device continuity.
* Sharing/public publishing and collaboration.
* Full schema editing, advanced item types, plugins/marketplace.
* Search, tagging systems, or long-form navigation beyond the first minute.
* **No full world imports/corpora in v0.1** (no bundled worlds, no importing large datasets as onboarding).
* Implementing the full **16-transition QDPI test matrix** inside onboarding (may exist as an internal test plan later).
* Payments, real-money purchase flows, transferability, redemption, exchange, or cash-out of Credits.

## 4) Design Principles

* **Default to Blank Field:** No pre-seeded Items; user creates their first objects.
* **Queue-first:** Creating an Item mints a **Queue** artifact (`type:"Q"`). There is no dropdown asking user to choose Q/M/D/H at creation.
* **Persistence is visible:** Every create/update shows a **Saved ✓** confirmation and a Ledger entry.
* **QDPI is explicit:** Interactions are tagged with **Queue / Monologue / Dialogue / Holologue** and logged as append-only QDPIEvents.
* **Bonds are prompts + connectors:** A Bond is a first-class object that is **draftable and executable**; execution produces lineage (inputs → bond → output item). Link-only Bonds (hololoops) are also first-class but never executed.
* **Hololinks are content-derived:** Hololinks must reference handles from both Items, not generic templates.
* **Holologue = general → specific artifact:** Holologue takes a constellation and produces **one concrete artifact Item** (multi-purpose; not a "summary" by default).
* **User confirmation matters:** Bonds are created/confirmed by the user (including choosing a suggested prompt and tapping **Create Bond**); no silent semantic links.
* **Fast path exists:** A user can complete onboarding with defaults in a few taps.
* **Append-only trust:** QDPIEvent log never rewrites history; it only appends.
* **Credits are inspectable:** Credits changes are visible as `credits.delta` events; the UI chip displays the derived balance.

## Locked Design Decisions (v0.1)

* **Onboarding starts in Blank Field immediately** (no mode choice).
* **Episode 0 / Session 0 is auto-created (YES).** Justification: a session container must exist immediately so QDPIEvents can be appended from second 1 and shown in the Ledger.
* **First Item is user-created and is Queue-type (`type:"Q"`)** titled "My First Field Item".
* **Queue Lattice Mode is enabled by default:** After creating Q2, system presents 4 hololoop options. User must select exactly 1 to persist a link-only Bond.
* **Minimum lattice size:** Default `QUEUE_LATTICE_MIN_Q = 4`. Until 4 Queue Items exist, operator execution (Q→M, Q→D, Holologue) is locked.
* **Bonds are user-confirmed** and may be created via:

  * (a) selecting from **4 suggested Bond prompts** and tapping **Create Bond**, or
  * (b) user-written Bond prompt text, or
  * (c) selecting 1 of 4 hololoop options (Queue Lattice Mode).
* **Bond lifecycle exists in v0.1:** `status: "draft" → "executed"`; executed Bonds MUST set `output_item_id`. Draft Bonds MUST have `output_item_id: null`. Link-only Bonds remain `status:"draft"` and are never executed.
* **Guided Tutorial Track (optional) guarantees** at least one Bond execution ("Run Bond") and one Holologue run ("Run Holologue"); the default Blank Field track does not require executing operators to complete.
* **Opening Ledger is a Queue/Inspect action** (not Holologue). Holologue tags are reserved strictly for Holologue runs/completions.

## 5) Personas

* **New User**

  * Goal: understand "what is this?" quickly; see proof it's not chat.
  * Needs: minimal setup, visible persistence, guided examples.
* **Returning User**

  * Goal: open existing Field immediately.
  * Needs: skip first-run; no forced tutorial.
* **Student mode**

  * Goal: learn operators through a guided mini workshop.
  * Needs: step-by-step moves, safe defaults, clear "what just happened" feedback.
* **Creator/Researcher**

  * Goal: generate concrete artifacts and preserve lineage.
  * Needs: quick execution, inspectable IDs, Ledger/JSON preview early.

## 6) Modes and Tracks

### A) Blank Field (default)

**Description:** Start with an empty Field and create Queue Items, build the Queue Lattice via hololoop selection, then unlock operators.
**Choose when:** You want to start building immediately without step-by-step guidance.

### B) Guided Tutorial Track (optional)

**Description:** Same Blank Field, but a guided mini workshop that teaches Queue Lattice Mode (Q1–Q4 + hololoops) and then three operator moves (Q→M, Q→D, (Q,Q)→H).
**Choose when:** You want a fast, structured introduction to Queue Lattice and Bond execution and Holologue artifact generation.

## 7) Screen-by-Screen Flow

### Global Notes (applies to both tracks)

* **Persistent objects:** `Item`, `Bond`, `Episode`, `QDPIEvent` (append-only)
* **ID format:** local ULID-style strings with prefixes: `ep_`, `it_`, `bd_`, `ev_`
* **Ledger:** persistent bottom-right button: **"Ledger"**
* **Privacy indicator:** top-left lock chip: **"Private"** (v0.1 is **Private • Local**)
* **Credits indicator:** top-right chip: **"Credits: 100"** (derived from `credits.delta` events)
* **Store commits:** after any object write, system appends `store.commit` QDPIEvent.
* **Credits updates:** any credits change appends `credits.delta` QDPIEvent; the Credits chip updates from the derived balance; all credits changes are inspectable in the Ledger.
* **Track toggle:** Guided Tutorial can be enabled/disabled from a small banner; it does not change the underlying data model.
* By default, QDPIEvents log user-meaningful actions (create/update/run/open); pure render/paint events are debug-only (off by default).

## 10) Edge cases (v0.1)

1. **User force-quits during first launch**

   * On next launch, app resumes in Blank Field; Episode 0 may already exist; append `app.resume` event; do not delete history.
2. **User creates Queue Items but never opts into Guided Tutorial**

   * Track A still functions; do not nag, but keep **Start Guided Tutorial** available until dismissed.
3. **User creates Q2 but dismisses hololoop selection**

   * System should prompt again or allow "bond later" with a warning. Default: require selection before proceeding.
4. **Bond draft created but user never executes**

   * Bond remains `status:"draft"` with `output_item_id:null`; Ledger clearly shows draft status. Append `bond.draft_created`; do not generate output.
5. **Bond execution requested but generation fails**

   * Bond stays `status:"draft"` with `output_item_id:null` (or retains draft with error metadata if supported); no output Item created; show modal: "Bond failed to run" with **Retry** and **Cancel**. Append `bond.execution_failed` and do not append `bond.executed`. Do not append `credits.delta` for `bond_executed`.
6. **Holologue requested with fewer than 2 Items selected**

   * Block run; show inline error: "Select 2 or more Items." Append `holologue.validation_failed`.
7. **Holologue generation fails**

   * No output Item created; show modal: "Holologue failed to generate artifact" + Retry. Append `holologue.failed`. Do not append `credits.delta` for `holologue_completed`.
8. **Duplicate taps on "Run Bond"**

   * Debounce; only one active execution per Bond.
9. **Storage write fails (disk full / permission / sandbox error)**

   * Block "Saved ✓"; show modal: "Can't save to Field" + Retry. Append `store.commit_failed` with error code.
10. **Returning user (data exists) opens app**

   * Skip first-run; open last Field; append `app.opened`. Tutorial banner hidden unless re-enabled from Settings.
11. **Clock/time skew**

* Use monotonic ordering key for QDPIEvents (ULID timestamp + sequence) to preserve append ordering even if wall-clock shifts.

## 13) Open Questions

1. When Bond execution fails, do we keep `status:"draft"` only, or introduce `status:"failed"` in v0.1?
2. Should `intent_type` be a free-text string, a small enum, or optional-only in v0.1?
3. If render/paint events are debug-only, which UI events (beyond open/close/request) are still worth logging in production without adding noise?
4. Should "Run Bond" be allowed from a Bond card only, or also from an Item context menu (v0.1 UX choice)?
5. How do we represent a Bond's "inputs" in UI without adding "prompt vs edge" terminology (e.g., "Inputs: 1 Item" vs a visual pill list)?
6. Holologue artifact options: should the modal offer fixed presets only, or allow a free-text "artifact target" in v0.1?
7. Should Holologue optionally propose Bonds as suggestions only (events), or also create draft Bonds automatically (currently: suggestions only)?
8. What is the minimum viable "provenance" structure for output Items that supports future replay without coupling to model internals?
9. Should Guided Tutorial completion create an explicit `tutorial.completed` event, and what are the completion criteria (Bond executed + Holologue completed + Ledger opened)?
10. Where should the "reset first-run / restart tutorial" control live in Settings without confusing returning users?
11. Should hololoop selection be required immediately after Queue Item creation, or can users defer bonding with a warning?
12. How should target Queue selection be presented: default previous Queue only, or a quick "target picker" chip list?
